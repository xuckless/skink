Skink shows git changes next to the line numbers and lets you stage, revert, commit and switch branches without leaving the editor.

Press <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>C</kbd> for the git panel, <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>D</kbd> to peek at the change under the cursor, and `:diff` to compare the file side by side.

## Gutter marks

Next to the line numbers, compared with the index:

- **Green bar**: added lines
- **Blue bar**: modified lines
- **Red mark**: deleted lines
- **Dotted bar**: a change that is already staged

The scrollbar (the editor's last column) shows the same marks for the whole file.

Turn them off with `"gitgutter": false`.

## Working with hunks

| Key | Command | Does |
|---|---|---|
| <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>N</kbd> | `:nexthunk` | Next change |
| <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>P</kbd> | `:prevhunk` | Previous change |
| <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>D</kbd> | `:hunk` | Peek at the change: <kbd>s</kbd> stage, <kbd>u</kbd> unstage, <kbd>r</kbd> revert, <kbd>Esc</kbd> |
| <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>S</kbd> | `:stagehunk` | Stage the change at the cursor |
| | `:unstagehunk` | Unstage it |
| | `:reverthunk` | Put the index version back |

Clicking a gutter mark opens the same peek. Reverting is a normal edit, so <kbd>Ctrl</kbd>+<kbd>Z</kbd> undoes it.

<Aside type="caution" title="Hold Shift">
The git keys are all <kbd>Alt</kbd>+<kbd>Shift</kbd> chords. The plain <kbd>Alt</kbd> versions do other things: <kbd>Alt</kbd>+<kbd>N</kbd> adds a cursor, <kbd>Alt</kbd>+<kbd>S</kbd> searches the project, <kbd>Alt</kbd>+<kbd>C</kbd> goes back to one cursor. If a chord does not reach Skink (macOS, tmux), type the command instead.
</Aside>

## Blame

- **Inline blame**: the faded author, date and summary at the end of the cursor line. On by default.
  - <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>B</kbd> (`:inlineblame`) toggles it.
  - `"inlineblame": false` turns it off for good.
- **`:blame`**: the whole file's blame in a tab. <kbd>Enter</kbd> on a line shows that commit.

## Diff

| Command | Shows |
|---|---|
| `:diff` | This file side by side against the index |
| `:diff HEAD` | This file against the last commit |
| `:diff all` | `git diff` of the whole tree, in a tab |

## The git panel

<kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>C</kbd> (or `:gitstatus`, `:status`) opens the panel. In it:

| Key | Does |
|---|---|
| <kbd>Enter</kbd> | Open the file |
| <kbd>s</kbd> / <kbd>u</kbd> | Stage / unstage the file |
| <kbd>S</kbd> / <kbd>U</kbd> | Stage / unstage all |
| <kbd>d</kbd> | Discard changes (asks first; untracked files go to the trash) |
| <kbd>c</kbd> | Commit |
| <kbd>C</kbd> | Amend |
| <kbd>b</kbd> | Branches |
| <kbd>z</kbd> / <kbd>Z</kbd> | Stash / list stashes |
| <kbd>g</kbd> | Refresh |
| <kbd>P</kbd> / <kbd>p</kbd> / <kbd>f</kbd> | Push / pull / fetch |

Push, pull and fetch run in a terminal tab, so git asks for passwords, passphrases and keys itself.

Skink never handles your credentials.

## Committing

- `:commit MESSAGE` commits with that message.
- `:commit` alone opens a message tab. Write the message and save it (<kbd>Ctrl</kbd>+<kbd>S</kbd>) to commit. Closing the tab cancels.
- In the message tab, `:amend` toggles amending the last commit and `:signoff` toggles a Signed-off-by line.

To use Skink for `git commit` run from a shell too, see [Use Skink as your $EDITOR](/skink/guides/skink-as-editor/).

`:stage [PATH]` and `:unstage [PATH]` work on the current file or `PATH`.

## Branches and stash

| Command | Does |
|---|---|
| `:branches` | List local branches. <kbd>Enter</kbd> switches, <kbd>D</kbd> deletes (asks first) |
| `:branch NAME` | Create `NAME` and switch to it |
| `:switch NAME` (`:checkout`) | Switch to a branch |
| `:stash [MESSAGE]` | Stash the current changes |
| `:stashes` | List stashes. <kbd>Enter</kbd> applies, <kbd>p</kbd> pops, <kbd>D</kbd> drops |
| `:push`, `:pull`, `:fetch [ARGS]` | In a terminal tab |
| `:git ARGS` | Run any git command, output in a tab |

## Merge conflicts

| Command | Does |
|---|---|
| `:conflicts` | Open every conflicted file at its first marker |
| `:nextconflict` / `:prevconflict` | Move between conflict blocks |
| `:ours` / `:theirs` / `:both` | Resolve the block under the cursor |

Conflict blocks are tinted: ours green, theirs blue.

The first line of each block shows "Accept ours | theirs | both", and you can click one. Every resolution is undoable.

## In the file tree

File names are coloured by status:

- modified: yellow
- added: green
- untracked: teal
- conflicted: red
- ignored: grey

A folder takes the colour of its most serious file.

## Requirements

Skink runs your installed `git` for these features, so it needs `git` on your `PATH`.
