Skink gets completion, errors, go to definition and the rest from language servers. Install the server for your language and put it on your `PATH`. Skink starts it the first time you open a file of that language, with no config.

Then <kbd>Ctrl</kbd>+<kbd>Space</kbd> completes, <kbd>Alt</kbd>+<kbd>G</kbd> goes to the definition and <kbd>Alt</kbd>+<kbd>R</kbd> lists references.

## Which language servers

| Language | Server Skink looks for | One way to install it |
|---|---|---|
| Rust | `rust-analyzer` | `rustup component add rust-analyzer` |
| TypeScript, JavaScript | `typescript-language-server` | `npm i -g typescript-language-server typescript` |
| Python | `basedpyright-langserver`, else `pyright-langserver` | `pip install basedpyright` or `npm i -g pyright` |
| Go | `gopls` | `go install golang.org/x/tools/gopls@latest` |
| Zig | `zls` | Your package manager, or a release from the zls project |
| Dart | `dart language-server` | Comes with the Dart (or Flutter) SDK |

Zig and Dart colours come from packages: `:install zig`, `:install dart`. Packages for other languages (Kotlin, Java, C/C++ and more) can bring their own language server, downloaded for you. See [Packages](/customize/packages/).

## Your own servers

Add or replace a server in `settings.json`:

```json
{
  "lsp.dart": "fvm dart language-server --protocol=lsp",
  "lsp.elixir": { "command": "elixir-ls", "extensions": ["ex", "exs"], "rootmarkers": ["mix.exs"] },
  "lsp.python": false
}
```

- A string is the command line. An object can also set `extensions`, `rootmarkers`, `initoptions` and `env`.
- `false` turns a language's server off.
- Names are `rust`, `typescript` (also `javascript`, `ts`, `js`), `python`, `go`, `dart`, `zig`, or a new one.

Changes apply at the next start. A project's `.skink/settings.json` can set servers too, but those only start after you trust the project.

## Several servers for one language

A list runs servers side by side. The first is the primary, and `"default"` stands for Skink's own server:

```json
{
  "lsp.python": ["default", "ruff server"],
  "lsp.typescript": [
    { "command": "typescript-language-server --stdio" },
    { "command": "vscode-eslint-language-server --stdio" }
  ]
}
```

Every server gets the open files. Problems, completions and code actions come from all of them. Hover, go to definition, rename, format and the rest go to the first server that offers them, primary first.

A list of plain words like `["gopls", "-remote=auto"]` is still one command with its arguments.

## Check and restart a server

`:lsp` shows the servers for the current file (primary and others), where their settings came from, its memory use and progress. If the server is missing or failed, it says why.

- `:lsp restart` restarts it.
- `:lsp log` shows its full log.

A server that crashes is restarted once automatically. One with no open files for 10 minutes is stopped and starts again when you need it, which keeps memory low.

## Keys and commands

| Key | Command | Does |
|---|---|---|
| <kbd>Ctrl</kbd>+<kbd>Space</kbd> | `:complete` | Completion list |
| <kbd>Alt</kbd>+<kbd>K</kbd> | `:hover` | Type and docs of the symbol at the cursor |
| <kbd>Alt</kbd>+<kbd>G</kbd> | `:definition` (`:def`) | Go to definition (several: a list) |
| <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>G</kbd> | `:typedef` | Go to the type's definition |
| <kbd>Alt</kbd>+<kbd>J</kbd> | `:peek` | Peek the definition in a popup |
| | `:implementation` (`:impl`) | Go to implementations |
| <kbd>Alt</kbd>+<kbd>R</kbd> | `:references` (`:refs`) | Every use, in a results tab (<kbd>Enter</kbd> jumps) |
| <kbd>Alt</kbd>+<kbd>Enter</kbd> | `:fix` or `:actions` | Code actions: quick fixes and refactorings |
| <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>R</kbd> | `:renamesymbol NEW` (`:rn`) | Rename the symbol everywhere |
| <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>F</kbd> | `:format` (`:fmt`) | Format the selection or the file |
| <kbd>Ctrl</kbd>+<kbd>R</kbd> | `:symbols` | Symbols in this file |
| <kbd>Alt</kbd>+<kbd>W</kbd> | `:allsymbols` | Symbols in the whole project |
| <kbd>Shift</kbd>+<kbd>F8</kbd> | `:problems` | Errors and warnings of the open files |
| <kbd>F6</kbd> / <kbd>Shift</kbd>+<kbd>F6</kbd> | `:nextproblem` / `:prevproblem` | Next / previous error or warning in this file |
| <kbd>Alt</kbd>+<kbd>U</kbd> / <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>U</kbd> | `:back` / `:forward` | Back to where you were before a jump, and forward again |
| <kbd>F1</kbd> | `:palette` | Every action and command. <kbd>F1</kbd> again on an entry opens its help |

While a debug session runs, <kbd>F6</kbd> pauses the program instead. See [Debugger](/code/debugger/).

## Completion

The list opens by itself after two letters or after `.`, `::` or `->`.

| Key | Does |
|---|---|
| <kbd>↑</kbd> / <kbd>↓</kbd> | Choose an item |
| <kbd>Enter</kbd> or <kbd>Tab</kbd> | Insert it |
| <kbd>Esc</kbd> | Close the list |

Docs for the selected item show beside the list. Snippets select their first placeholder; <kbd>Tab</kbd> moves to the next one.

### Turn off the automatic popup

Set `"autocomplete": false`. <kbd>Ctrl</kbd>+<kbd>Space</kbd> still works.

### Signature help

Signature help opens after `(` and `,`, showing the parameters of the call you are typing.

## Errors and warnings

Diagnostics show in the gutter and as red and yellow marks on the scrollbar (the editor's last column).

<kbd>F6</kbd> steps through them. <kbd>Shift</kbd>+<kbd>F8</kbd> or `:problems` lists all of them in a tab.

A lightbulb in the sign column means the cursor line has code actions: press <kbd>Alt</kbd>+<kbd>Enter</kbd>, or type `:fix`.

To send the errors to an AI agent, press <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>E</kbd>. See [AI agents](/tools/ai-agents/).

## Format on save

```json
{ "formatonsave": true }
```

With this, <kbd>Ctrl</kbd>+<kbd>S</kbd> asks the language server to format the file first.

<kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>F</kbd> (or `:format`) formats on demand.

## Inlay hints

Inline type and parameter hints from the server are off by default. Turn them on with:

```json
{ "inlayhints": true }
```

## Rename and other multi-file edits

Rename (<kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>R</kbd>) and code actions that touch several files open the refactor preview, where you check which changes to apply. See [Refactoring](/code/refactoring/).

## Breadcrumbs and quick open

The status line shows where the cursor is, like `impl Foo > fn bar`.

Quick open (<kbd>Alt</kbd>+<kbd>P</kbd>, or `:recent`) switches mode by its first character:

- `@` for symbols in the file
- `#` for symbols in the project
- `>` for commands

## Folding

When the server offers folding ranges (`#region`, import blocks, comment blocks), <kbd>Alt</kbd>+<kbd>M</kbd> folds those. Without a server, folds follow indentation. See [Sessions and folding](/editing/sessions-and-folding/).

## When nothing happens

- Run `:lsp`. If it says the server is not installed, install it and make sure your shell's `PATH` has it, then `:lsp restart`.
- Files of 8 MB or more open as LARGE, without a language server.
- Over SSH, the server has to be installed on the server.
- Inside [EveryAI](/tools/everyai/), language servers come from EveryAI instead.
