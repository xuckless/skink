Mac terminals type a character for <kbd>Option</kbd>+key (<kbd>Option</kbd>+<kbd>Z</kbd> gives `Ω`), which would break every <kbd>Alt</kbd> shortcut. Skink reads those characters back as the <kbd>Alt</kbd> chord whenever that chord does something, so most shortcuts just work.

For the few that cannot be read back, set your terminal to send Option as Alt. Or skip Alt entirely: every key also has a typed command.

## What Skink does by default

With the default `"macoptionisalt": "auto"`:

- <kbd>Option</kbd>+<kbd>Z</kbd> zooms and <kbd>Option</kbd>+<kbd>P</kbd> opens quick open, because those <kbd>Alt</kbd> chords are bound.
- Where the chord means nothing, the character is typed. You can still write `Ω` in a plain buffer.

### The macoptionisalt setting

| Value | Behaviour |
|---|---|
| `"auto"` | Translate an Option character only when the matching Alt chord is bound (default) |
| `"always"` | Translate every Option character to an Alt chord, on any platform |
| `"never"` | Type the characters as they are |

```json
{ "macoptionisalt": "always" }
```

## Dead keys need a terminal setting

<kbd>Option</kbd>+<kbd>E</kbd>, <kbd>I</kbd>, <kbd>N</kbd>, <kbd>U</kbd> and <kbd>&#96;</kbd> are dead keys. They wait for the next letter to make an accented character, so Skink never sees them.

To use those chords, and for the most reliable result overall, tell your terminal to send Option as Alt:

<Tabs>
  <TabItem label="Ghostty">
    In the Ghostty config:
    ```text
    macos-option-as-alt = left
    ```
    The left Option becomes Alt; the right one still types special characters. Skink also turns on the kitty keyboard protocol in Ghostty.
  </TabItem>
  <TabItem label="iTerm2">
    **Profiles → Keys → Left Option key: Esc+**
  </TabItem>
  <TabItem label="Terminal.app">
    **Settings → Profiles → Keyboard → Use Option as Meta key**
  </TabItem>
  <TabItem label="Kitty">
    In `kitty.conf`:
    ```text
    macos_option_as_alt left
    ```
  </TabItem>
  <TabItem label="WezTerm">
    In `wezterm.lua`:
    ```lua
    send_composed_key_when_left_alt_is_pressed = false
    ```
  </TabItem>
  <TabItem label="Alacritty">
    In the Alacritty config:
    ```toml
    option_as_alt = "OnlyLeft"
    ```
  </TabItem>
</Tabs>

Setting only the left Option keeps the right one for typing characters like `€` or `ü`.

## Keys that never need Alt

If you would rather not change anything, these do their jobs without <kbd>Option</kbd>:

| Job | Use |
|---|---|
| Command palette (every action) | <kbd>F1</kbd> |
| Quick open (instead of <kbd>Option</kbd>+<kbd>P</kbd>) | `:recent` |
| Zoom (instead of <kbd>Option</kbd>+<kbd>Z</kbd>) | `:zoom` |
| Show or hide dotfiles (instead of <kbd>Option</kbd>+<kbd>H</kbd>) | `:dotfiles` |
| Debugging | <kbd>F5</kbd> start / continue, <kbd>F9</kbd> breakpoint, <kbd>F10</kbd> step over |
| Undo | <kbd>Ctrl</kbd>+<kbd>Z</kbd> |
| Any other key | <kbd>Ctrl</kbd>+<kbd>E</kbd>, then type its command |

<Aside type="note" title="Every key has a typed command">
Press <kbd>Ctrl</kbd>+<kbd>E</kbd>, type the name (for example `comment`, `files` or `peek`) and press <kbd>Enter</kbd>. <kbd>F1</kbd> shows each action's command beside its key. See [Every key has a typed command](/skink/start/typed-commands/).
</Aside>

## Cmd keys and F-keys

<kbd>Cmd</kbd> shortcuts belong to your terminal (copy, paste, new window), not to Skink.

Some laptops need <kbd>Fn</kbd> for F-keys. Check your keyboard settings, or turn on "Use F1, F2, etc. keys as standard function keys" in macOS Keyboard settings.
