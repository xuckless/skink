If you like Neovim for what surrounds the editing but not the modes, you have two choices. You can bend Neovim toward modeless editing with mappings, or you can use an editor that is modeless by design and ships the IDE features itself.

Skink is the second kind: no Normal mode, mouse and trackpad first, and LSP, tree-sitter, git, a terminal and AI agents built in. Like Neovim, it lives in the terminal, works over SSH and starts fast.

## Can you make Neovim modeless?

Partly. Vim has an old "easy" mode (`vim -y` / `evim`) that keeps you in Insert mode and maps common shortcuts. In Neovim you can map desktop keys in Insert mode:

```lua
-- init.lua: a few desktop-style keys in Insert mode
vim.keymap.set("i", "<C-s>", "<Cmd>write<CR>")
vim.keymap.set("i", "<C-z>", "<Cmd>undo<CR>")
vim.keymap.set("i", "<C-q>", "<Cmd>quit<CR>")
vim.opt.mouse = "a"
vim.opt.keymodel = "startsel,stopsel"  -- Shift+arrows start a selection
vim.opt.selectmode = "mouse,key"       -- typing replaces the selection
```

This gets you far, but plugins, help and documentation all assume Normal mode. You keep hitting places where <kbd>Esc</kbd> is expected. It is a workaround, not a different editor.

## What "modeless" means in practice

- Every printable key types. Commands use <kbd>Ctrl</kbd>, <kbd>Alt</kbd> or function keys.
- Selection is <kbd>Shift</kbd>+movement or a mouse drag, and typing replaces it.
- There is never a state where you have to look at the screen to know what a key will do.

The trade-off is real: Vim's operator + motion grammar (`ci"`, `dap`, `.`) is more expressive than chorded shortcuts. Modeless editors close the gap with multiple cursors, syntax-aware selection and a command palette.

## How Skink covers Vim habits

Every key in the table also has a typed command: press <kbd>Ctrl</kbd>+<kbd>E</kbd>, type the name, press <kbd>Enter</kbd>. If you think in ex commands, that may feel more natural than chords. See [typed commands](/editing/typed-commands/).

| Vim habit | Skink key | Typed command |
|---|---|---|
| `ciw`, `viw` | <kbd>Ctrl</kbd>+<kbd>D</kbd> selects the word, then type | `:addcursor` |
| `vi(`, `vaf` | <kbd>Alt</kbd>+<kbd>O</kbd> grows the selection to the enclosing syntax node, <kbd>Alt</kbd>+<kbd>I</kbd> shrinks it | `:expand` / `:contract` |
| `*` then `cgn` and `.` | <kbd>Ctrl</kbd>+<kbd>D</kbd> repeatedly adds a cursor at each next match; <kbd>Alt</kbd>+<kbd>X</kbd> skips one | `:addcursor` / `:skipcursor` |
| Visual block `Ctrl-v` | <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>↑</kbd> / <kbd>↓</kbd> adds cursors above / below | `:cursorabove` / `:cursorbelow` |
| `dd`, `yy`, `p` | <kbd>Ctrl</kbd>+<kbd>X</kbd> / <kbd>Ctrl</kbd>+<kbd>C</kbd> with no selection act on the line; <kbd>Ctrl</kbd>+<kbd>V</kbd> pastes | `:cut` / `:copy` / `:paste` |
| `ddp`, `:m` | <kbd>Alt</kbd>+<kbd>↑</kbd> / <kbd>↓</kbd> move lines | `:moveup` / `:movedown` |
| `gcc` | <kbd>Ctrl</kbd>+<kbd>/</kbd> or <kbd>Alt</kbd>+<kbd>/</kbd> | `:comment` |
| `%` | <kbd>Ctrl</kbd>+<kbd>]</kbd> | `:bracket` |
| `qq` ... `@q` | <kbd>Ctrl</kbd>+<kbd>U</kbd> to record, <kbd>Ctrl</kbd>+<kbd>J</kbd> to replay | `:record` / `:replay` |
| `za` | <kbd>Alt</kbd>+<kbd>M</kbd> folds by indentation | `:fold` |
| `Ctrl-o` / `Ctrl-i` | <kbd>Alt</kbd>+<kbd>U</kbd> / <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>U</kbd> | `:back` / `:forward` |

| `:w`, `:q`, `:e`, `:vs` | Still work in the command line (<kbd>Ctrl</kbd>+<kbd>E</kbd>) | `:w`, `:q`, `:e`, `:vs` |

### Rebind keys in bindings.json

Every action has a name you can bind in `~/.config/skink/bindings.json`, in Micro's format. There, a lowercase letter after `Alt-` means the plain key, so `Alt-j` is <kbd>Alt</kbd>+<kbd>J</kbd>:

```json
{
  "Alt-j": "MoveLinesDown",
  "Alt-k": "MoveLinesUp",
  "Ctrl-5": "JumpToMatchingBrace"
}
```

This example replaces the defaults for <kbd>Alt</kbd>+<kbd>J</kbd> (peek definition) and <kbd>Alt</kbd>+<kbd>K</kbd> (hover). Those stay reachable as `:peek` and `:hover`.

## Mouse and gestures

This is where a modeless design pays off: the mouse never fights a mode.

### In the text

- **Click** to place the cursor, **drag** to select, **<kbd>Alt</kbd>+click** to add or remove a cursor.
- **Wheel** scrolls; **<kbd>Shift</kbd>+wheel or a horizontal trackpad swipe** scrolls long lines sideways, with line numbers staying put.

### Around the text

- **Tabs:** click to switch, middle-click or the `x` to close.
- **Splits:** drag the divider or a pane's title row to resize; click a pane to focus it.
- **Gutter:** click a git mark to peek at the change (stage, unstage or revert from there), click a fold mark to open it.
- **Sticky scroll headers:** click one to jump to that block.
- **Merge conflicts:** click "Accept ours | theirs | both" above the block.
- **Terminal tabs:** programs inside get the mouse too; <kbd>Ctrl</kbd>+click a `file:line` to open it.

All of it works over SSH and inside tmux (with `set -g mouse on`). See [mouse and trackpad](/editing/mouse-and-trackpad/).

## The IDE parts you would otherwise install

- **LSP** for Rust, TS/JS, Python, Go, Dart and Zig, started on first use: completion, hover, definition, references, code actions, rename, format, inlay hints.
- **tree-sitter** colours for 10 languages built in and more as packages, with injections (code in Markdown fences, `script` and `style` in HTML).
- **Fuzzy quick open** (<kbd>Alt</kbd>+<kbd>P</kbd>, or `:recent`) and **project search** (<kbd>Alt</kbd>+<kbd>S</kbd>) that respect `.gitignore`.
- **Git:** gutter, hunks, blame, panel, diff, conflicts.
- **Terminal tabs** and a bottom dock (<kbd>Alt</kbd>+<kbd>T</kbd>).
- **AI agents** over ACP: Claude Code, Gemini CLI, Codex and more.
- **A debugger** (DAP) for gdb, lldb, debugpy and Delve.
