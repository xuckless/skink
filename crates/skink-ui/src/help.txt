Skink help
==========

Skink is a lightweight, modeless terminal editor. Everything it shows opens as
a tab, the same way a file does: files, this help, command output, git diffs,
merge conflicts, your settings, and terminals.

## Getting started
  skink FILE[:LINE[:COL]]   open a file (jump to a position)
  skink DIR                 open a folder: file tree + empty buffer
  skink                     empty scratch buffer
  Ctrl-E                    command line (type `help` any time; Tab completes)
  Alt-P                     quick open: open tabs, recent files, project files
  Ctrl-Q                    close the tab (quits when it is the last file tab)

## Tabs
  The tab bar is at the top. File tabs and terminal tabs live side by side.
  Click a tab to select it, its x (or middle-click) to close it.
  Alt-1 .. Alt-9            jump to tab N
  Ctrl-PageUp/PageDown      previous / next tab (Alt-, and Alt-. also work in files)
  Ctrl-T                    new empty file tab
  Ctrl-O                    open a file or folder by path
  F12                       toggle between the current file and your terminal tab
  Shift-F12                 open another terminal tab
  F11                       close the active terminal tab (steps into while debugging)
  F8                        file tree (show / move focus / back to the editor)
  Ctrl-B                    hide / show the file tree sidebar
  Terminal tabs show the title set by the program inside, like Ghostty.
  Run an AI CLI in one: `:term claude`, `:term gemini`, ... (or use the AI
  prompt box and :agent, see "AI").
  In a terminal tab every key goes to the program, except Alt-1..9 and the
  F-keys / Ctrl-PageUp/PageDown that are bound to tab actions (ToggleTerminal,
  NewTerminal, CloseTerminal, ToggleTree, ToggleSidebar, PreviousTab, NextTab), so they can
  be rebound in bindings.json. A finished terminal closes on any key.

## Search in files
  Alt-s (or Ctrl-Shift-F)   search every file in the project     :grep [TEXT]
             Alt-R regex, Alt-C case, Alt-W whole word, as in the find bar.
             Results stream into a tab grouped by file; Enter jumps.
             Honours .gitignore / .ignore; stops at 5000 matches.
  :greprep WITH     replace the last search's matches in every file through
             the refactor preview (regex mode expands $1). :stopsearch stops.
  :sgrep PATTERN    structural search (ast-grep) in files of the current
             file's language: code with $NAME for one node and $$$NAME for
             any number, e.g. :sgrep foo($A, $$$REST). Whitespace and
             comments don't matter.
  :srep PATTERN => WITH   rewrite every structural match through the
             preview, e.g. :srep foo($A, $B) => bar($B, $A). After :sgrep,
             :greprep WITH does the same with the searched pattern.

## Tasks
  Shift-F10  pick a task and run it in a terminal tab        :task [LABEL]
  Shift-F9   run the last task again                         :task last
  Tasks come from .skink/tasks.json and .vscode/tasks.json (VS Code subset:
  label, command, args, options.cwd, options.env, group, problemMatcher, and
  per-OS "linux" / "osx" / "windows" overrides; ${workspaceFolder}, ${file},
  ${relativeFile}, ${fileDirname}, ${fileBasename}, ${env:NAME} expand), plus
  ones detected from Cargo.toml, package.json scripts (npm / pnpm / yarn /
  bun), go.mod, build.zig, pytest setups and Makefile targets.
  When a task ends its output goes through problem matchers ($rustc, $tsc,
  $eslint-stylish / -compact, $go, $gcc, python tracebacks and pytest; with
  no problemMatcher all of them are tried, [] turns them off). The problems
  show in the gutter, Shift-F8 and F6 like a language server's, until the next run.

## Debugging
  F5          start debugging (the last configuration, else pick one); continue
  Shift-F5    stop the program (twice: kill the debug adapter)   :debug restart
  F10 / F11 / Shift-F11   step over / into / out (only while debugging; then
              F10 is Quit, F11 closes a terminal, Shift-F11 terminal history)
  F6          pause while the program runs (else next diagnostic)
  F9          breakpoint on the cursor line; or click the sign column
  Alt-F9      condition, hit count or logpoint:
              :breakpoint if i > 3 · :breakpoint hits 5 · :breakpoint log x={x}
              :breakpoint clear (this file) · :breakpoint clearall
  Alt-L       debug panel: state, call stack (Enter shows a frame), variables
              (Enter / Space expands), watch (w adds, d removes), breakpoints
              (Enter jumps, d removes), console (e evaluates)
  Alt-K       while paused: the value of the word or selection at the cursor
  :debug      pick a configuration · :debug NAME · :debug eval EXPR ·
              :debug watch EXPR · :debug pause · :debug panel
  While paused the stopped line is highlighted (@ / ▶ in the sign column) and
  values of local variables show at the end of the lines above it.
  Breakpoints follow edits and are kept in the session with the watches.
  Configurations come from .skink/launch.json and .vscode/launch.json (VS Code
  subset: name, type, request launch/attach, preLaunchTask runs a task first,
  per-OS overrides; every other field goes to the adapter, ${...} expanded),
  plus defaults: each cargo binary (built with cargo build first), the Python
  file or the pytest test at the cursor, the Go package or Go test at the
  cursor, and a native program built next to the file (cc -g x.c -o x).
  Adapters, found on PATH:
    gdb        GDB 14+ (gdb -i dap): C, C++, Rust, Zig     type "gdb"
    lldb-dap   LLVM (formerly lldb-vscode)                 type "lldb-dap"
    codelldb   CodeLLDB                                    type "lldb"
    debugpy    pip install debugpy (python -m debugpy.adapter)  type "debugpy"
    dlv        Delve (dlv dap)                              type "go"
    js-debug   not supported yet (it needs child debug sessions)
  Programs an adapter asks to run in a terminal (debugpy's
  "console": "integratedTerminal") open in a terminal tab.

## Sessions
  `skink` with no arguments inside a project (a folder with .git, Cargo.toml,
  package.json, go.mod, pyproject.toml or build.zig, or below one) reopens the
  files, cursors, split panes, file tree and shells (in their last folder) it
  had when you quit there. Opening a file or folder starts fresh and does
  not overwrite the saved session. Off with "restoresession": false.

## Folding, sticky scroll, rulers
  Alt-M      fold / unfold the block at the cursor (by indentation)   :fold
  Alt-Shift-M  open every fold      :foldall closes every top-level block
             A closed fold shows a mark in the gutter (click it to open)
             and "N lines" after its first line; the cursor steps over it,
             and jumping into it (search, go to line) opens it.
  Sticky scroll: the headers of the blocks you are scrolled into stay at
             the top (click one to go there). "stickyscroll": false turns
             it off.
  Rulers:    "rulers": [80, 100] in settings.json (Micro's "colorcolumn"
             works too).

## Jumps, marks and notes
  Alt-U      back to where you were before a jump (definition, results,
             quick open, :goto)                                   :back
  Alt-Shift-U  forward again                                      :forward
  Scrollbar marks: the editor's last column marks errors (red), warnings
             (yellow), find matches (orange) and the cursor (blue) across
             the whole file.
  Notes from background work (search done, session restored, idle language
  servers stopped) show briefly in the top-right corner.

## Split panes
  Ctrl-\     split side by side (legacy terminals: Ctrl-4)   :vsplit [FILE]
  Alt-\      split top and bottom                             :split [FILE]
  Ctrl-W     next pane      Alt-Shift-W previous pane
  Alt-Q      close the focused pane (its tab stays open)      :unsplit, :only
  Alt-= / Alt--   grow / shrink the focused pane; or drag the divider or a
             pane's title row with the mouse.
  Every pane shows one tab. A file shown in two panes is one buffer with two
  cursors: edits appear in both. Clicking a pane focuses it; switching tabs
  changes the focused pane. A terminal shows in one pane at a time.
  Docks:     Alt-T  a shell along the bottom (again: hide it; the shell
             keeps running in its tab)                        :termdock
             Alt-Shift-T  the agent panel on the right        :agentdock

## File tree
  Which pane has the keys is always visible: the focused tree shows
  "Files  (focused)", an accent border and an accent selection, the status line
  says TREE, and the editor hides its cursor. Clicking or scrolling the tree
  focuses it; clicking the editor or a tab hands the keys back.
  Up/Down/PageUp/PageDown/Home/End move, Enter/Right open or expand, Left
  collapses or jumps to the parent, . shows hidden files.
  Alt-H  show / hide dotfiles from anywhere (also :hidden, :tree hidden); it
         works with the tree hidden too and applies when it opens.
  a  new file in the selected folder ("src/x/y.rs" creates the folders too)
  A  new folder          -  collapse all          *  expand the folder recursively
  r / F2  rename or move (edit the path; new folders are created; open tabs follow).
          Running language servers are asked first (willRenameFiles); the
          imports and module paths they would change open in the refactor preview.
  d / Delete  move to the OS trash (asks first)
  y  copy the absolute path      Y  copy the path relative to the root
  /  filter files as you type (whole project, .gitignore respected); Esc clears
  < / >  narrower / wider (or drag the right border; actions TreeNarrower / TreeWider)
  q / Esc back to the editor, h hide. Commands: :new PATH, :mkdir PATH,
  :tree collapse | expand | hide | hidden.
  Git-ignored entries are dimmed and never auto-expanded. The tree follows the
  active file, remembers open folders per project, and hides itself in
  windows narrower than 50 columns.

  More roots: :addroot DIR adds another project folder below the main
  root's entries; quick open and project search cover it too, and the
  session remembers it. :removeroot [DIR] takes it away again.

## Editing
  Keys follow Micro; the full table is under "Key bindings" below.
  Selection: Shift + movement keys, mouse drag, Ctrl-A (all).
  Scrolling: the wheel scrolls lines; Shift+wheel or a trackpad swipe scrolls
  long lines sideways (the line numbers stay put) until the cursor moves.
  ScrollLeft / ScrollRight are bindable actions.
  Brackets: the pair around the cursor is underlined; Ctrl-] jumps to the other
  one (JumpToMatchingBrace). With syntax, brackets in strings and comments are
  ignored. Terminals without the kitty keyboard protocol send Ctrl-] as Ctrl-5;
  bind it in bindings.json if needed: {"Ctrl-5": "JumpToMatchingBrace"}.
  Undo/redo: Ctrl-Z / Ctrl-Y.   Clipboard: Ctrl-C / Ctrl-X / Ctrl-V
  (Ctrl-C with no selection copies the line, Ctrl-X cuts it).
  Alt-Up / Alt-Down move lines. Ctrl-Shift-D duplicates. Tab / Shift-Tab indent / outdent.

## Macros
  Ctrl-U     start / stop recording keys (the status bar shows ● REC)
  Ctrl-J     replay the last recording (ToggleMacro / PlayMacro, as in Micro)

## Lines, case and syntax selection
  Alt-O / Alt-I   grow / shrink the selection to the enclosing syntax node
  :JoinLines  :SortLines  :UpperCase  :LowerCase  :TitleCase  :TrimTrailingWhitespace
  (bind any of them in bindings.json). Case actions work on the selection or
  the word at the cursor; join and sort on the selected lines; all are one
  undo step and run at every cursor.

## Typing helpers
  Brackets and quotes close themselves; typing the closer steps over it,
  Backspace between an empty pair deletes both, and with a selection they wrap
  it. Quotes do not pair inside words (don't). "autoclose": false turns it off.
  Enter after ( [ { indents one level and puts the closer on its own line; a
  closer typed on a blank line goes back one level.
  Tab inserts the file's indentation (tabs or spaces, detected from the file;
  "tabstospaces": true picks spaces for files without indentation yet).
  Alt-/ or Ctrl-/ toggles line comments on the selected lines (ToggleComment),
  using the file type's token (//, #, --, ...).

## Multiple cursors
  Ctrl-D (or Alt-N) selects the word under the cursor; again adds a cursor at
  the next match. Alt-X skips this match, Alt-Shift-Up/Down or Ctrl-Alt-Up/Down
  add a cursor above / below, Alt-click adds or removes one. Esc (or Alt-C)
  goes back to one cursor. Typing, deleting, moving, indenting and moving
  lines happen at every cursor, and one undo undoes them all. Copy with N
  cursors puts one line per cursor on the clipboard; pasting N lines into N
  cursors gives each cursor its own line. The status line shows ×N.
  Actions: SpawnMultiCursor, SpawnMultiCursorUp/Down, SkipMultiCursor,
  RemoveMultiCursor, RemoveAllMultiCursors (Micro's names).
  Ctrl-Shift-D needs the kitty keyboard protocol; elsewhere it arrives as Ctrl-D.
  Ctrl-F opens the find bar: it searches as you type from the cursor, marks
  every visible match and shows "N of M". Alt-R regex, Alt-C case-sensitive
  (default is smart case: lowercase matches any case), Alt-W whole word; the
  active toggles show in the prompt (.* Aa \b). Enter keeps the match, Esc
  goes back to where you were. Ctrl-N / Ctrl-P next / previous match with the
  same options. Ctrl-L go to line.
  Alt-S searches only inside the selection the bar opened with ([sel]); a
  selection over several lines starts that way. Tab moves to "Replace with":
  Enter replaces every match (in the selection or file) as one undo step; in
  regex mode $1 / ${name} insert capture groups.
  The cursor moves, and Backspace / Delete remove, whole characters as you
  see them: emoji with modifiers or joiners, accented letters, flags.
  A thin thumb on the bottom row appears when lines are wider than the view.
  :replace FIND WITH replaces every match in the selection (or the whole
  file) as one undo step; quote text with spaces: :replace "a b" "c".

## Typed commands for every key
  Any key can be swallowed by a terminal, the OS or a keyboard layout (macOS
  Option, Windows console, tmux). Every key therefore also has a command: press
  Ctrl-E and type it. Tab completes, Up/Down recall history.
  Short names: :comment :duplicate :moveup :movedown :expand :contract
  :bracket :indent :outdent :addcursor :cursorabove :cursorbelow :onecursor
  :find :findnext :findprev :palette :hover :peek :typedef :fix :allsymbols
  :nextproblem :prevproblem :nexttab :prevtab :newtab :nextsplit :prevsplit
  :files :sidebar :dotfiles :newterm :toggleterm :ask :senderrors :record
  :replay :rerun :nextprompt :prevprompt :lastoutput :continue :step :stepin
  :stepout :pause :condition, plus the existing ones (:def :refs :fold :zoom
  :nexthunk :blame :gitstatus ...).
  Any action also runs by its own name in any spelling: :ToggleComment,
  :toggle-comment and :togglecomment are the same. F1 shows each action's key
  and its command; :help ends with the full key table and the command per key.

## Code intelligence (language servers)
  Servers start on first use for Rust (rust-analyzer), TS/JS
  (typescript-language-server), Python (basedpyright or pyright), Go (gopls),
  Dart (the Dart SDK's `dart language-server`) and Zig (zls) when installed
  (or come from EveryAI when Skink runs inside it).
  Your own servers, in settings.json:
    "lsp.dart": "fvm dart language-server --protocol=lsp"     replace the command
    "lsp.elixir": {"command": "elixir-ls", "extensions": ["ex", "exs"],
                   "rootmarkers": ["mix.exs"], "initoptions": {}, "env": {}}
                                                             add a language
    "lsp.python": false                                     no server for .py
  Names: rust, typescript (also javascript, ts, js), python, go, dart, zig, or
  any new one. :lsp shows the server a file gets, where it came from and where
  it was found on PATH. Changes apply the next time Skink starts.
  Ctrl-Space  completion list; it also opens by itself after two letters or
              `.`, `::`, `->` (setting "autocomplete"). Up/Down choose, Enter/Tab
              insert, Esc closes; docs show beside the list. Snippets select their
              first placeholder; Tab moves to the next one.
  Alt-K       type and docs of the symbol at the cursor
  Alt-G       go to definition (several: a list)   Alt-Shift-G  type definition
  Alt-J       peek the definition in a popup       :impl  implementations
  Alt-R       references in a results tab (Enter jumps)
  Alt-Enter   code actions (quick fixes, refactorings)
  Alt-Shift-R rename the symbol everywhere (:renamesymbol NEW, :rn)
  Edits that touch several files (rename, code actions) open the refactor
  preview: files and hunks with checkboxes and a side-by-side diff.
  Up/Down move, Space toggles, a all, n none, Enter applies the checked ones
  (one undo step per file), Esc cancels.
  :safedelete  delete the function / struct / class at the cursor (with its doc
              comments and attributes) once find-references shows no use outside
              it; uses are listed instead. :safedelete! previews it unchecked.
  :mv PATH     move or rename the current file (relative to the project root);
              servers update imports (willRenameFiles) through the preview.
  :extract var|fn [NAME]  extract the selection with the server's code action;
              extract var works without a server for Rust, TS/JS and Python.
  Alt-Shift-F format the selection or file; "formatonsave": true formats on Ctrl-S
  Ctrl-R      symbols in this file   Alt-W  symbols in the project
  F1          command palette (every action and command)
  Shift-F8    problems in the open files (Enter jumps)   F6 / Shift-F6 next / previous
  Signature help opens after `(` and `,`. Breadcrumbs (impl Foo > fn bar) are in
  the status line. "inlayhints": true shows type and parameter hints.
  Quick open (Alt-P, or :recent) switches list by its first character: `>` commands,
  `@` symbols in the file, `#` symbols in the project. Files stream in from the
  whole project (.gitignore respected, no limit); a `/` in the query matches path
  segments in order (s/c/grade finds src/color/grade.rs). Matched letters are
  highlighted, and wide terminals show a preview of the selected file.
  :lsp shows the server, its memory and progress; :lsp restart, :lsp log.
  A crashed server is restarted once automatically; one with no open files for
  10 minutes is stopped and starts again when needed. A lightbulb in the sign
  column means the cursor line has code actions (Alt-Enter).

## Themes
  :theme lists every theme and previews the selected one as you move (Esc
  puts the old one back, Enter keeps the pick for this session). To keep it,
  set "colorscheme": "NAME" in settings.json. Built in: tokyonight-night,
  tokyonight-storm, tokyonight-moon, tokyonight-day, catppuccin-mocha,
  catppuccin-latte, gruvbox-dark, gruvbox-light, high-contrast.
  "colorscheme": "auto" (the default) is Tokyo Night, day or night after the
  terminal's background: COLORFGBG when set, else Skink asks the terminal
  (OSC 11, at most 250 ms, after the first frame) on terminals known to
  answer (Ghostty, kitty, WezTerm, iTerm2, Terminal.app, Alacritty, foot,
  VS Code, GNOME/VTE, Konsole, tmux); others get the dark one.
  Your own themes: <config>/themes/NAME.json, for example
    {"name": "Mine", "base": "gruvbox-dark", "colors": {"bg": "#1d2021"}}
  Only bg and fg are required without a base; the rest is mixed from them.
  Colours: bg bg_dark bg_hl bg_sel bg_search bg_popup fg fg_dim comment
  line_nr guide blue cyan green orange purple red yellow teal type operator
  punct diff_ours diff_theirs diff_add diff_del debug_line. Micro
  colorschemes load as they are, from <config>/colorschemes/NAME.micro or
  Micro's own ~/.config/micro/colorschemes. Terminal tabs take their 16 ANSI
  colours from the theme.

## Languages
  Syntax colours (tree-sitter): Rust, TypeScript/TSX, JavaScript, Python, Go, Zig,
  Dart, JSON, TOML, Bash, Markdown, YAML, HTML, CSS, Lua, Make, INI, diff, XML/SVG.
  Embedded code is coloured too: Markdown code fences and inline markup, HTML
  <script> and <style>. Builds with --features all-langs add C, C++, Java, C#,
  Ruby, PHP, SQL, Elixir, Haskell, Swift, Scala, Nix and Svelte.

## Previews
  Alt-V (or :preview) on a Markdown file opens a live, rendered preview in a tab:
  headings, emphasis, lists, task lists, quotes, tables, rules and syntax-coloured
  code fences. It follows your edits and opens scrolled to where you were. Enter
  on a link opens it (web links in the browser, relative ones as files). Images
  show their alt text. Alt-V again goes back to the source.
  SVG files preview as half-block pixels (+ / - / 0 zoom). Raster images
  (PNG, JPG) are not previewed yet.

## AI
  Skink talks to an ACP agent (Claude Code via claude-code-acp, Gemini CLI,
  opencode, Goose, Antigravity, Codex) started in the background, or to
  EveryAI's agents when running inside it. Settings:
    "ai.agent": "auto"            Claude Code first (claude-code-acp, or your
                                  installed `claude` through npx, which reuses its
                                  login), then gemini, opencode, goose, agy. Or a
                                  name: "claude" (also "claude code",
                                  "claude-code-acp"), "gemini" ("gemini-cli"),
                                  "opencode", "goose", "antigravity" ("agy"),
                                  "codex"; case, spaces, - and _ do not matter.
                                  Missing adapters run through npx when they can.
                                  Or a command: ["my-agent", "--acp"]
  Rewrite and implement answers are code: ask for comments or an explanation
  and the agent writes them as comments in the code. An answer without code
  opens in an "AI answer" tab instead of being lost.
  settings.json and bindings.json accept // comments and trailing commas.
    "ai.model": "default"         or a model the agent offers; loose names work:
                                  "opus 5.5", "opus5.5", "claude-opus-5-5"
    "ai.effort": "default"        low, medium, high, max. Claude Code: thinking
                                  budget 4k / 10k / 20k / 32k tokens; other agents:
                                  their reasoning-level option over ACP, if any
    "ai.model.rewrite": "..."     per mode: rewrite, ask, search, implement
    "ai.effort.rewrite": "low"    (same modes)
  :settings puts a reference of agents, models and effort at the top of the
  file. Saving a change to ai.agent / ai.model / ai.effort tests the agent with
  a one-line chat in a throwaway folder (removed afterwards, with Claude Code's
  transcript of it) and shows "Claude Code ✓ (model …, effort …)" or why not.
  :agents     supported agents, installed or not, the active one, last check
  :agents check   run the test now
  Ctrl-G      prompt box for the selection (nothing selected: the code around
              the cursor). Enter sends, Alt-Enter newline, Shift-Tab mode
              (rewrite, implement, ask, search), Tab cycles the model, Up/Down
              history, Esc closes. While it works the status line shows the
              agent, mode, seconds and what it is doing; Esc cancels.
              In the box: @file (fuzzy, Tab/Enter completes), #rule (from
              AGENTS.md / AGENT.md walk-up and .skink/rules/*.md), @selection,
              @diagnostics, @terminal (screen of the last terminal tab);
              /model NAME, /ask, /search, /implement, /rewrite.
  rewrite / implement  the answer appears as a diff in the file itself:
              removed lines struck through in red, added lines in green under
              them. y accept, n reject, u undecided, Up/Down / ] [ / Tab move
              between changes, Enter apply (undecided count as accepted),
              a or Ctrl-Enter accept all, Esc discard. One undo step.
  ask         the answer streams into a read-only tab.
  search      the agent's hits open in a results tab (Enter jumps).
  Alt-Shift-A agent panel (:agent [message]): a chat with tool calls and the
              plan; Ctrl-G there types a message, with the same chips (@file,
              #rule, @selection of the file tab, @diagnostics, @terminal).
              :agent cancel stops the turn, :agent stop ends the agent,
              :agent send sends the selection or the terminal's screen.
  Alt-Shift-E :agent errors: the errors to the agent: in a terminal tab its
              last command and output (the block since the previous prompt),
              elsewhere the open files' errors and warnings (else the last
              terminal command). Files the agent writes are staged, never written
              directly: they open in the refactor preview when its turn ends
              (:review reopens them).
  Permission requests from the agent show a dialog: Up/Down, Enter or 1-9
  answers, Esc rejects. :model [NAME] shows / sets the model for this run.

## Views
  Help, command output and git views open as read-only tabs. Opening the same
  view again reuses its tab. `:run CMD` runs in the background in the project
  root (the editor never freezes); the tab fills in when it finishes.

## Files on disk
  Saves are atomic (temp file + rename, permissions and symlinks kept), so a
  crash or full disk never leaves half a file. Encoding is kept as read: UTF-8,
  UTF-8 with BOM, UTF-16 LE/BE; other bytes open read-only (RO) so a save cannot
  corrupt them. :set eol=lf|crlf changes line endings on the next save.
  Changed on disk: clean files reload by themselves (Ctrl-Z undoes); with
  unsaved edits Skink asks: (k)eep mine / (t)ake disk / (d)iff. Saving over a
  file changed since it was read asks first. Checked when the terminal regains
  focus, on tab switches and while you work (at most every 2 s, never idle).
  Unsaved edits are backed up to the state dir after a 3 s pause; after a crash,
  opening the file offers (r)ecover / (d)iscard.
  Permission denied on save: Skink offers sudo and runs `sudo tee` in a
  terminal tab (where sudo can ask for your password); the tab closes once the
  file on disk matches. Files of 2 MB or more open as LARGE: no syntax colours,
  no language server.

## Command line (Ctrl-E)
  Up/Down browse history, Tab completes command names and paths, Esc cancels.
  Any editor action can also be run by name, e.g. `:Save`, `:SelectAll`,
  `:ConflictNext`; see "Actions" below.

## Merge conflicts
  :conflicts      open every file git reports as conflicted, at the first marker
  :nextconflict / :prevconflict   move between <<<<<<< blocks
  :ours / :theirs / :both         resolve the block under the cursor (undoable)
  Conflict blocks are colored: ours (green tint), theirs (blue tint). The
  first line of each block shows "Accept ours | theirs | both": click one.

## Git
  Gutter marks next to the line numbers compare the buffer with the index:
  green bar added, blue bar modified, red mark lines deleted; a dotted bar is
  a change that is already staged. The scrollbar shows them too.
  Alt-Shift-N / Alt-Shift-P   next / previous change   (:nexthunk / :prevhunk)
  Alt-Shift-D     peek at the change: s stage, u unstage, r revert, Esc
                  (clicking a gutter mark does the same)
  Alt-Shift-S     stage the change at the cursor (:stagehunk, :unstagehunk,
                  :reverthunk; reverting is a normal edit, Ctrl-Z undoes it)
  Alt-Shift-B     toggle the faded blame of the cursor line (on by default; :inlineblame)
  :blame          the whole file's blame in a tab; Enter shows the commit
  :diff           this file side by side against the index; :diff HEAD
                  against the last commit; :diff all is `git diff` of the tree
  Alt-Shift-C     the git panel (:gitstatus, :status). In it:
                  Enter open, s / u stage / unstage, S / U all, d discard
                  (asks first; untracked files go to the trash), c commit,
                  C amend, b branches, z stash, Z stashes, g refresh,
                  P push, p pull, f fetch (in a terminal tab, so git asks
                  for passwords and keys itself)
  :commit [MSG]   commit MSG, or open a message tab: saving it commits;
                  :amend and :signoff toggle those options; closing cancels
  :stage / :unstage [PATH]    this file or PATH
  :branches  :branch NAME  :switch NAME    list (Enter switches, D deletes,
                  asks first), create + switch, switch
  :stash [MSG]  :stashes      stash; list (Enter apply, p pop, D drop)
  :push / :pull / :fetch [ARGS]    in a terminal tab
  The file tree colours names: modified yellow, added green, untracked teal,
  conflicted red, ignored grey; folders take the colour of their worst file.
  Settings: "gitgutter": true, "inlineblame": true (set false to hide it).

## Skink as your $EDITOR
  git config --global core.editor skink      commit messages, rebase lists
  export EDITOR=skink VISUAL=skink           Ctrl-G in Claude Code / Codex,
                  crontab -e, bash/zsh edit-command-line, kubectl and gh edit
  Files a tool hands its editor open lean: one buffer, no file tree, project
  scan, language server, git gutter, update check, session or recents. Picked
  the way other editors do it: git's own files by name (COMMIT_EDITMSG,
  MERGE_MSG, TAG_EDITMSG, SQUASH_MSG, git-rebase-todo, addp-hunk-edit.diff),
  and any file that belongs to no project (no .git or Cargo.toml / package.json
  / go.mod / pyproject.toml / build.zig above it), like a single-file window in
  VS Code or Zed. That covers the temp files AI tools and shells hand over.
  :mode says which and why.
  The bottom line shows the keys: Ctrl-S save, Ctrl-Q done (asks if unsaved),
  :cq leave without saving and exit 1, so git aborts the commit or rebase.
  Commit messages: rulers at 50 and 72 (unless "rulers" is set), # lines
  dimmed, a note when the subject passes 50 characters.
  Rebase lists: Alt-Shift-K cycles pick, reword, edit, squash, fixup, drop on
  the cursor line (:rebase VERB sets one); Alt-Up / Alt-Down reorder commits.
  Notes and prompts (temp files): Markdown colours when the file is .md or has
  no extension; the cursor starts at the end.
  skink --scratch FILE forces lean mode, skink --project FILE the full editor.
  Inside a Skink terminal tab, skink FILE (yours, git's, an AI tool's) opens
  as a tab of that Skink instead of a second editor in the terminal, and the
  command waits until the tab closes: Ctrl-Q there finishes (exit 0), :cq
  cancels (exit 1). Other files open as normal tabs and return at once. The
  tab's shell gets SKINK_IPC and SKINK_IPC_TOKEN; env -u SKINK_IPC skink FILE
  edits inside the terminal instead.

## Settings and key bindings
  :settings opens settings.json, :bindings opens bindings.json (created with
  defaults when missing). Saving settings.json applies it; else run :reload.
  :settings project opens this project's .skink/settings.json: its keys
  override yours for this workspace (the folder Skink opened), and saving it
  applies it. Either file can hold language sections:
    "[rust]":   {"tabsize": 4, "formatonsave": true, "lsp": "rust-analyzer"},
    "[python]": {"tabsize": 4, "rulers": [88]}
  A section is named by language (rust, typescript, tsx, javascript, python,
  go, dart, ...) or by file extension ("[md]").
  Opening or saving settings.json, a project's .skink/settings.json or
  bindings.json checks it: bad JSON, unknown keys (with "did you mean"), wrong
  types and out-of-range values show in the gutter and the problems list
  (Shift-F8), at the key. Inside a key's quotes, the completion list offers
  every setting with its description. JSON schemas for both files are written
  to the state folder (schema/) and handed to vscode-json-language-server
  when it is installed.
  settings.json   {"tabsize": 4, "icons": "auto|nerd|ascii", "syntax": true, "indentguides": true,
                   "updates": "notify|auto|off"}
  bindings.json   Micro format, key name -> action:  {"Ctrl-j": "Save", "Alt-g": "command-edit:goto "}
  Key names: Ctrl-x, Alt-x, Shift-Up, CtrlShiftRight, F5, PageDown, Backtab ...
  Actions can be chained: "Copy|CopyLine" runs the first that works,
  "Escape,Deselect" runs both. "command-edit:TEXT" opens the command line
  pre-filled. Config lives in ~/.config/skink (or $SKINK_CONFIG_DIR).

## Terminals, AI agents and EveryAI
  Terminals are real terminal emulators (colors, mouse, alternate screen), so
  any AI CLI runs unchanged. Inside EveryAI, Skink finds the host through
  SKINK_HOST_URL and SKINK_HOST_TOKEN and hands language servers and agent
  management over to it; the status bar then shows "EveryAI". The prompt box
  and the agent panel then run on EveryAI's AI (prompt.run); Tab and /model
  pick from EveryAI's models.list, and ai.model / per-mode models match its
  ids or names. Without it Skink
  runs language servers itself (rust-analyzer, typescript-language-server,
  basedpyright, gopls, zls when installed).
  Shift-F11  the terminal's history in a tab (:scrollback): Ctrl-F searches
             it, Shift+arrows select (keyboard copy mode), Ctrl-C copies,
             Enter on a file:line[:col] line opens it there.
  Ctrl-click a file:line[:col] in a terminal to open it.
  Shift-F2 / Shift-F3  previous / next shell prompt   Shift-F4  select the
             last command's output (:scrollback last). These use prompt marks
             (OSC 133), which Skink adds to the bash, zsh, fish and PowerShell
             it starts in terminal tabs: your own rc files (oh-my-zsh, starship,
             ...) load first and unchanged, and are never edited. Off with
             "terminal.shellintegration": false. Other shells and programs get
             no marks; then Alt-Shift-E guesses the last command from the
             screen. With marks, Alt-Shift-E sends exactly the last output.

## Updates
  skink --upgrade          install the latest release in place (also: skink upgrade)
  skink --upgrade --check  only report whether a newer release exists
  skink --upgrade --version 0.1.0   install that release (can downgrade)
  :upgrade                 the same from inside the editor, in the background
  When GitHub's download links fail (5xx, timeouts), the files come through
  the GitHub API instead; GH_TOKEN or GITHUB_TOKEN raises its rate limit. The
  checksum is checked the same way either way.
  With "updates": "notify" (default) Skink checks GitHub at most once a day and
  says so in the status line; "auto" also installs (used from the next start);
  "off" never checks. SKINK_NO_UPDATE_CHECK=1 or CI turn the check off.
  Installs owned by cargo, Homebrew, scoop or winget print that tool's command.
  Release builds check a minisign signature on SHA256SUMS when the project
  signs its releases; SKINK_ALLOW_UNSIGNED=1 accepts older, unsigned ones.

## Zoom
  Alt-Z, :zoom       zoom pane: only the text (tab bar, tree and status line hidden; the
                     status line returns while a prompt or message is up)
  Font size belongs to the terminal: its own keys (Ctrl-= / Ctrl-- in most)
  are left unbound. :fontsize (:font) +1 | -1 | 0 (actions FontBigger, FontSmaller,
  FontReset) asks EveryAI when Skink runs inside it, or Kitty when remote
  control is allowed (allow_remote_control in kitty.conf).

## macOS: Option as Alt
  Mac terminals type a character for Option+key (Option+Z gives "Ω"), which
  would break every Alt binding. Skink reads those characters back as the Alt
  chord when that chord does something (setting "macoptionisalt": "auto", the
  default; "always" translates every Option character, "never" none). So
  Option+Z zooms, Option+P quick-opens, but Ω still types in a plain buffer
  wherever Option+Z means nothing. Dead keys (Option+E, I, N, U, `) cannot be
  read back; set your terminal to send Option as Alt for those:
    Ghostty      macos-option-as-alt = left   (left Option is Alt, the right
                 one still types special characters); Skink also turns on the
                 kitty keyboard protocol in Ghostty, Kitty and WezTerm
    Kitty        macos_option_as_alt left
    WezTerm      send_composed_key_when_left_alt_is_pressed = false
    iTerm2       Profiles > Keys > Left Option key: Esc+
    Terminal.app Settings > Profiles > Keyboard > Use Option as Meta key
    Alacritty    option_as_alt = "OnlyLeft"
  Keys that never need Alt: F1 command palette, :recent quick open, :zoom,
  :dotfiles, F5 / F9 / F10 debugging. Ctrl-Z is always Undo.
  Every key also has a typed command: Ctrl-E, then its name (:comment,
  :nexthunk, :files, ...). The key table at the end of :help lists them, and
  any action runs by its own name in any spelling (:toggle-comment).

## Icons and fonts
  Icons are Nerd Font glyphs. The font belongs to your terminal (Ghostty, Kitty
  and WezTerm already include Nerd Font symbols). SKINK_ICONS=ascii or
  "icons": "ascii" in settings.json switches to plain text.
